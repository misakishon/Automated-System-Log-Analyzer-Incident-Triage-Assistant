LogGuard AI

Automated IT Administration Solution: Local IT System Log Triage, Continuous Multi-Port Watcher & Autonomous Incident Diagnostics Assistant

1. Executive Overview & Problem Addressed

In modern enterprise IT environments, system administrators are inundated with raw log streams spanning web applications, reverse proxies, and database tiers. Manual inspection during outages drastically increases Mean Time to Resolution (MTTR). Furthermore, enterprise data compliance prevents uploading sensitive server logs (containing IPs, database table names, and customer records) to commercial public cloud LLMs.

LogGuard AI is an automated IT administration solution engineered to solve these challenges. Powered by an on-premises Gemma 3 (4B) model running through Ollama, it ingests server logs in real time, isolates unhandled exceptions, and delivers instant root-cause analysis, severity classifications, and exact remediation instructions with zero cloud transmission.

3. The 4-Port Ecosystem Architecture

To prevent port collisions with existing enterprise services, LogGuard AI decouples services across four dedicated ports:

Port Service Name URL Role in System
:8000 Target Application http://localhost:8000 Target web application (e.g. Iconect, Laravel, or Node). Emits exceptions, DB timeouts, and errors to disk.
:8080 LogGuard Dashboard http://localhost:8080 Primary administrative GUI (Laravel 13 + React 19). Hosts the 24/7 Watcher, live auto-triage badge, and audit trail.
:5000 Python Bridge & Hub http://localhost:5000 Python microservice (app.py). Probes all ports, serves file reads, and proxies Gemma 3 triage requests.
:11434 Local Ollama Engine http://localhost:11434 Hardware-accelerated local AI inference server executing gemma3:4b without internet connectivity.

4. How Running app.py Orchestrates & Connects All Open Ports

Executing python app.py (or python app.py --open) activates the system orchestrator and bridge:

  • Socket Port Matrix: Instantly probes ports 8000, 8080, 5000, and 11434 via TCP socket connections and displays a live formatted status matrix in the terminal.
  • Interactive Web Hub (Port 5000): Serves an interactive status dashboard displaying real-time green/red health indicators for every port with direct 1-click launch buttons.
  • Auto-Launch Feature (--open): Automatically launches default browser tabs for both the LogGuard Dashboard (:8080) and the Port Hub (:5000).
  • One-Click Gemma 3 Verification: Includes a web button that sends a test database deadlock incident to Gemma 3 to verify model responsiveness in ~12 seconds.

5. Operational Flow: Error Detection, Auto-Triage & Safety

  • Port Error Detection: Nginx 502/504 errors, MySQL 3306 deadlocks, and Redis 6379 timeouts are captured by the application and written to storage/logs/laravel.log. LogGuard monitors this unified log on disk.
  • Incident Isolation: To prevent hallucinations caused by outdated errors, LogGuard isolates only the single newest active error block from the tail (slice(-1)), discarding legacy stack traces.
  • Live Visual Loading Indicator: The ⚡ Auto-Triage (On New Errors) toggle illuminates with an amber pulsing ring, bouncing icon, and live seconds counter ([ ⟳ Triaging... (Xs) ]) whenever an error triggers Gemma 3.
  • Safety Controls (--dry-run): In dry-run mode, the system parses logs and outputs structured remediation reports in simulation mode without making destructive changes or stressing the GPU.

6. System Prerequisites & Installation Steps

A. Prerequisites

  • PHP: Version 8.2 or higher with pdo, curl, and mbstring extensions.
  • Composer: PHP dependency manager.
  • Node.js: v18.0.0 or higher with npm.
  • Python: Version 3.10 or higher with flask, flask-cors, and requests.
  • Ollama: Installed locally with the gemma3:4b model downloaded.

B. Execution Guide

# 1. Start Ollama local server
ollama serve

# 2. In a separate terminal, verify model is ready
ollama run gemma3:4b

# 3. Start LogGuard AI Dashboard on Port 8080
cd C:\TrainAi\agenticAI
php artisan serve --port=8080

# 3. Start Target Application on Port 8000 (e.g. Iconect)
cd C:\TrainAi\Iconect
php artisan serve --port=8000

# 4. Start Python Bridge & Multi-Port Hub (automatically opens browser)
cd C:\TrainAi\agenticAI
python app.py --open

7. Test Scenarios & Operational Proofs

Test Scenario 1: Automated Detection of Concurrency Deadlock

  • Input Event: SQLSTATE[40001]: Serialization failure: 1213 Deadlock found when trying to get lock; try restarting transaction at OrderController.php:84.
  • Automated Detection: LogGuard classifies severity as CRITICAL within 5 seconds.
  • AI Triage Output: 
    Root Cause: High concurrency lock contention on database table causing transaction serialization failure.
Affected Components: OrderController.php, MySQL Database (InnoDB Engine).
Remediation: Wrap database operations inside DB::transaction() with automated retry attempts (3 retries).
Verification Commands:
  - SHOW ENGINE INNODB STATUS;
  - tail -n 50 storage/logs/laravel.log | grep -E 'ERROR|CRITICAL'

Test Scenario 2: 24/7 Headless CLI Daemon Execution

To run LogGuard as an autonomous background service without opening a web browser:

# Execute headless daemon with continuous 3-second polling & automated triage
php artisan logguard:watch --path="C:\TrainAi\Iconect\storage\logs\laravel.log" --auto-triage

The daemon tails the log stream, prints real-time color-coded terminal alerts, and automatically invokes Gemma 3 (4B) to generate remediation reports whenever critical failures are written to disk.
